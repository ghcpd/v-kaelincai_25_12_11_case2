5) New system design (greenfield replacement)
5.1 Target state (concise)
- Decompose into:
  - API Gateway / Edge
  - Orchestration Service (stateless API + durable state machine)
  - Durable State Store (events DB / transactions table)
  - Outbox + Worker (durable outbox for external calls)
  - Provider Adapter (thin connector)
  - Observability plane (structured logs, traces, metrics)
- Guarantees:
  - Idempotent APIs (Idempotency-Key at entry)
  - Retry with exponential backoff and jitter
  - Timeouts, circuit-breaker per external provider
  - Compensation via Saga orchestrator or outbox-driven compensating actions
  - Unified state machine to represent lifecycle (INIT → PENDING → CONFIRMED → COMPENSATED → FAILED)

5.2 Service decomposition (short)
- appointment-api: HTTP entrypoint, validates requests, issues idempotency key, persists intent.
- orchestrator: executes state transitions, writes outbox messages for side-effects.
- outbox-worker: reads outbox, sends to provider, updates state, emits compensating outbox on failures.
- provider-adapters: small modules encapsulating provider HTTP semantics.
- audit/reconciliation job: periodic verification, fixes drift.

5.3 Idempotency / Retry / Timeout / Circuit-breaker / Compensation (rules)
- Idempotency:
  - Accept Idempotency-Key header (<=64 chars, ASCII); store mapping (key → final result).
  - If present and mapping exists, return stored result (200).
- Retry:
  - Retry on network errors & 5xx with exponential backoff: base 200ms, multiplier 2, max attempts 3–5.
  - Jitter added to prevent thundering herd.
- Timeout:
  - External provider calls: set per-call timeout (e.g., 1.5s for availability, 2.0s for booking).
- Circuit breaker:
  - Per-provider: open after N consecutive failures (e.g., 3); reset after T (e.g., 60s).
  - While open return 503 with reason=circuit_open and run async fallback (shadow/backoff).
- Compensation / Saga:
  - Two options:
    - Orchestration-based Saga: orchestrator coordinates steps and issues compensating calls on failure.
    - Outbox-based eventual approach: write intent + outbox message (book), outbox worker sends call and writes result; if confirm fails, enqueue cancel via outbox.
  - Use transactional outbox to avoid dual-write issues.

5.4 Architecture diagram (ASCII)
Client --> API Gateway --> appointment-api --> Orchestrator --> (Durable Store + Outbox)

                                           v                           v
                                    Outbox Worker -----------------> Provider
                                           ^
                                           | (compensation)
                                          Reconciliation
